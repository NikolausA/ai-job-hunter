# Tech Stack (Технологический стек проекта)

Документ фиксирует полный технологический стек проекта AI Job Hunter, чтобы вся команда могла быстро ориентироваться, избегать расхождений и принимать решения, согласованные с архитектурой.

## 1. Frontend

**Next.js 14 (App Router)**

- Полное использование app/ маршрутизации.

- Серверные компонентов (Server Components) — по умолчанию.

- Клиентские компоненты ("use client") — только когда необходим state/UI-интерактивность.

- Server Actions — опционально, но предпочтение отдаётся tRPC.

**Причины выбора:** производительность, SSR/ISR, удобство работы с API, нативная интеграция с React 18.

**React 18 + TypeScript**

- Компонентный подход.

- Строгая типизация.

- React Hooks для управления состоянием и побочными эффектами.

**Причины:** прозрачность, предсказуемость, поддерживаемость.

**Tailwind CSS**

- Утилитарные классы.

- Быстрое прототипирование и визуальная консистентность.

**Причины:** скорость разработки, отсутствие необходимости писать много кастомного CSS.

**UI-библиотеки и утилиты**

- Headless UI — модальные окна, переключатели, списки.

- Radix UI / shadcn/ui — если нужно более развитое UI.

- React Hook Form + Zod Resolver — формы и строгая валидация.

## 2. Backend

**tRPC**

Используется для связи фронтенда и бекенда в едином type-safe-стеке.

- Никаких REST-эндпоинтов.

- Схемы валидации — через Zod.

- Контекст включает:

* Prisma Client

* пользователя (если авторизован)

* токен / userId (через NextAuth middleware)

**Причины:** instant DX, автотипизация на клиенте, отказоустойчивость, минимум бойлерплейта.

**Prisma ORM**

- Генерация типобезопасного клиента.

- Миграции.

- Модель данных:

* User

* Profile

* Job

- Под капотом — PostgreSQL.

**Причины:** скорость, безопасность, понятность схемы, мощный клиент.

**PostgreSQL**

- Основная БД проекта.

- Запускается через Docker Compose.

```

services:
db:
image: postgres:15
environment:
POSTGRES_USER: postgres
POSTGRES_PASSWORD: postgres
POSTGRES_DB: jobhunter
ports: - "5432:5432"
volumes: - pgdata:/var/lib/postgresql/data

```

**Причины:** надёжность, транзакционность, лучшая поддержка сложных запросов, структурированные данные.

**NextAuth.js**

- Авторизация пользователей.

- Email + password (CredentialsProvider).

- Хранение пользователей — в PostgreSQL через Prisma.

- JWT-сессии.

**Причины:** актуальный стандарт для Next.js, отлично интегрируется с App Router.

## 3. Testing

**Vitest**

- Тесты tRPC-роутов.

- Unit-тесты вспомогательных функций.

- Моки Prisma.

- Globals (beforeAll, afterAll, describe, it).

**Причины:** быстрый раннер, совместим с Vite, не конфликтует с Next.js.

**Testing Library (Frontend)**

Будет добавлена на этапе разработки UI.
Цель — покрытие компонентных сценариев.

## 4. DevOps / Инфраструктура

**Docker**

- Локальная БД PostgreSQL.

- Будущая контейнеризация приложения.

**ESLint + Prettier**

- Строгий линтинг.

- Автоформатирование.

**Git + Conventional Commits**

- Сog-сompliant workflow.

- В связке с Decisions Log.

## 5. Инструменты разработки

**Zod**

- Схемы данных и валидации.

- Используется на уровне:

* tRPC input schemas

* form validation

* сущностей доменной логики

**SuperJSON**

- Сериализация дат, объектов, ошибок.

- Используется как transformer в tRPC.

**Turso (опционально)**

Может быть рассмотрена как альтернатива Postgres, если потребуется edge-ready архитектура.
Пока НЕ используется.

## 6. Архитектурные соглашения

**FSD (Feature-Sliced Design)**

Используется на фронтенде:

- shared/

- entities/

- features/

- widgets/

- pages/

**Серверная структура**

Серверная часть — в /src/server/:

- /trpc/ — маршруты, роутеры, контекст

- /db/ — prisma client

- /auth/ — next-auth реализации

- /utils/ — вспомогательные функции

## 7. Описание ключевых связок

**Frontend <-> Backend**

tRPC полностью заменяет REST и GraphQL:

```

app/
└─ client/page.tsx
↳ client.job.getAll() // типизированный вызов

```

**Backend <-> Database**

Prisma Client → PostgreSQL.

## 8. Ограничения и рекомендации

- Никаких axios/fetch для API — только tRPC.

- Никакого Redux — используем локальный стейт + серверные компоненты tRPC.

- Минимум глобального состояния.

- Никакого CSS-модуля — только Tailwind.

- Строго типобезопасные операции.
