# Functional Specification — AI Job Hunter

Дата: 2025-11-25

---

## 1. Краткое назначение

**AI Job Hunter** — веб-приложение для помощи соискателю в поиске и отклике на вакансии. Основная ценность: выдавать релевантные вакансии и генерировать персонализированные сопроводительные письма с помощью AI-интеграций.

Целевые пользователи:

- соискатели (основные потребители)
- (в будущем) работодатели/администраторы

---

## 2. Цели и требования (high-level)

**Обязательные (MUST):**

1. CRUD для вакансий (создание, получение, детали).
2. Пользовательский профиль с навыками и профилями (Profile).
3. Получение профилей по `userId`.
4. Безопасная авторизация (NextAuth) — минимум Credentials provider.
5. tRPC API с Zod-валидацией.
6. Построение и работа с БД PostgreSQL (через Prisma).
7. Возможность seed-ить тестовые данные и запускать миграции.
8. Возможность деплоя на Vercel (frontend) и Supabase (DB) или аналог.

**Желательно (SHOULD):**

- Интеграция с OpenAI для генерации cover letters и embeddings.
- Реaltime уведомления (WebSocket) о новых подходящих вакансиях.

**Дополнительно (NICE-to-have):**

- Фильтры и поиск по вакансиям.
- История откликов/статусов.

## 3. Список функций / пользовательские истории

Каждая история содержит: цель, критерии приёма (acceptance criteria), приоритизацию.

### 3.1. Регистрация / Авторизация (MUST)

**Как**: пользователь должен зарегистрироваться и залогиниться.
**Что**: Credentials provider (email + password) + опционально GitHub OAuth в будущем.
**Критерии приёма:**

- Пользователь может создать учётную запись.
- Пользователь может логиниться/логаутиться.
- Сессия хранится и доступна в tRPC-контексте.

### 3.2. Просмотр списка вакансий — job.getAll (MUST)

**Как**: на странице `GET /` или `app/jobs` пользователь видит список вакансий.
**Критерии приёма:**

- Запрос `job.getAll` возвращает массив вакансий.
- Каждый элемент содержит `id, title, company, location, tags, createdAt`.

### 3.3. Просмотр вакансии — job.getById (MUST)

**Как**: пользователь открывает страницу вакансии `/jobs/:id`.
**Критерии приёма:**

- Запрос `job.getById({id})` возвращает полную сущность вакансии.
- 404 при несуществующем id (через `findUniqueOrThrow`).

### 3.4. Создание вакансии — job.create (MUST)

**Как**: авторизованный пользователь (admin/creator) создаёт вакансию через форму.
**Критерии приёма:**

- Ввод валидируется Zod-схемой.
- После успешного создания вакансия появляется в `getAll` и имеет корректные поля.
- Ответ содержит созданную запись с `id`.

### 3.5. Профили пользователя — profile.getByUser (MUST)

**Как**: на странице профиля пользователя показываются его профили/резюме.
**Критерии приёма:**

- Запрос `profile.getByUser({ userId })` возвращает массив профилей.
- Если у пользователя нет профилей — вернуть пустой массив.

### 3.6. Информация о пользователе — user.getById (MUST)

**Как**: получить публичную информацию о пользователе (name, skills).
**Критерии приёма:**

- `user.getById({ id })` возвращает объект `User` или 404.

### 3.7. Seed & Dev tooling (MUST)

**Как**: запуск `npm run db:seed` создаёт тестовые данные.
**Критерии приёма:**

- Seed idempotent (не создаёт дубли при повторном запуске).
- В репозитории есть README-инструкция как поднять Docker DB и выполнить миграции.

### 3.8. Тестирование (MUST)

**Как**: покрытие tRPC-роутов интеграционными и unit тестами (Vitest).
**Критерии приёма:**

- Тесты запускаются и проходят локально.
- В CI прогонять базовые тесты (опционально позже).

### 3.9. AI-интеграция (SHOULD)

**Как**: интеграция с OpenAI для генерации cover letters и embeddings.
**Критерии приёма:**

- Модуль `ai/` умеет делать 2 вещи: `generateCoverLetter(profile, job)` и `createEmbedding(text)`.
- Роут `job.recommendations` использует embeddings для поиска похожих вакансий (pooled index/Supabase vector).

## 4. API и контракты (tRPC routes)

Ниже — в виде карт пользователю и потребителю API.

### 4.1. jobRouter

- `getAll(): Job[]` — возвращает упрощённые поля.
- `getById({id: string}): Job` — полная сущность.
- `create(input: CreateJobInput): Job` — создаёт вакансию.

**CreateJobInput (Zod)**

```ts
z.object({
  title: z.string().min(3),
  company: z.string().min(1),
  description: z.string().min(10),
  location: z.string().optional(),
  tags: z.array(z.string()).optional(),
});
```

### 4.2. profileRouter

- `getByUser({ userId: string }): Profile[]`

### 4.3. userRouter

- `getById({ id: string }): User`
- `getUserWithProfiles({ id: string }): User | null` (optional)

**Типы** — синхронизируются с Prisma-моделями и Zod-схемами в `src/shared/types`.

## 5. UI-страницы и flow

Список ключевых страниц и минимальные требования к ним.

### 5.1. Главная — `/` (jobs list)

- Компоненты: `JobsList`, `JobCard`.
- Использует `trpc.job.getAll.useQuery()`.

### 5.2. Страница вакансии — `/jobs/[id]`

- Компоненты: `JobDetail`, `ApplyButton`.
- Использует `trpc.job.getById.useQuery({ id })`.

### 5.3. Профиль пользователя — `/profile/[userId]`

- Компоненты: `ProfileHeader`, `ProfileList`.
- Использует `trpc.profile.getByUser.useQuery({ userId })` и `trpc.user.getById.useQuery({ userId })`.

### 5.4. Админ/Создание вакансии — `/jobs/create` (auth required)

- Компоненты: `JobForm` (react-hook-form + zodResolver).
- Использует `trpc.job.create.useMutation()`.

## 6. Acceptance criteria (общие)

- Все API имеют Zod-схемы и проходят валидацию.
- tRPC endpoints типизированы и работают с Prisma.
- UI использует tRPC client и корректно обрабатывает loading / error states.
- Seed + миграции описаны и работают.

---

## 7. Ограничения и допущения

- В первой версии не реализуем поиск по состоянию, только фильтры по тегам и location.
- AI-функционал интегрируется отдельно, его реализация может зависеть от доступности OpenAI API и бюджета.
